5.4. Vistas, Blade y layouts

La V de MVC

El HTML, por fin separado de la lógica

Segunda fila del plan del bloque: "HTML mezclado con PHP → vistas Blade y layouts". Las rutas de 5.3 pasan a devolver vistas. Tecla S: vista del ponente. Tecla O: vista general.

De HTML con PHP a vistas

En v0

El foreach, el HTML y el e() de cada dato, en el mismo fichero.

Cada página repetía <head>, cabecera y pie (o pie(), en 2.4).

En Laravel

Las vistas, en resources/views/, solo presentan.

Reciben los datos ya preparados. Es la V de MVC (5.2).

Devolver una vista


Route::get('/', function () {
    return view('home', ['centro' => config('marcapersonalfp.centro')]);
});
  • home → resources/views/home.blade.php, sin carpeta ni extensión
  • Subcarpetas con puntos: proyectos.index → proyectos/index.blade.php
  • Cada clave, una variable: 'centro' => … → $centro. Dato a dato: ->with('id', $id)

php artisan make:view proyectos.index

Blade compila a PHP

  1. Se pide la vista: resources/views/proyectos/index.blade.php
  2. La primera vez, Blade la compila: {{ }} → echo e(), @foreach → foreach
  3. PHP ejecuta la versión compilada y genera el HTML
  4. Las siguientes, directamente la compilada, mientras no cambies el .blade.php
Paso 2: mismo color, misma equivalencia. Azul: las dobles llaves son echo con e(), el escape de 3.6. Ámbar: las directivas son la sintaxis alternativa de 3.2. El foreach compilado está simplificado: Blade añade también lo necesario para $loop. Lo verán en el ejercicio 6 (Investiga).

Mostrar datos

En v0En Blade
<?= e($alumno) ?>{{ $alumno }}
<?= e($video ?? 'Sin vídeo') ?>{{ $video ?? 'Sin vídeo' }}
<?= $html ?> (sin escapar){!! $html !!}
<?php // comentario ?>{{-- comentario --}}

{{ }} escapa siempre. {!! !!}, solo con HTML nuestro, nunca con datos del usuario.

Los comentarios de Blade no llegan al navegador; los <!-- -->, sí.

Estructuras de control

Directivas que empiezan por @: la sintaxis alternativa de 3.2, sin etiquetas.


@if ($proyecto['metadatos']['calificacion'] >= 5)
    <p>Aprobado</p>
@elseif ($proyecto['metadatos']['calificacion'] >= 4)
    <p>Casi</p>
@else
    <p>Suspenso</p>
@endif

@isset($id)
    <p>Visualizar el currículo de {{ $id }}</p>
@endisset

@foreach ($proyectos as $id => $proyecto)
    <li>{{ $proyecto['nombre'] }}</li>
@endforeach

$loop y @forelse

$loop->iterationNúmero de vuelta, desde 1
$loop->first / lasttrue en la primera / la última
$loop->countNúmero de elementos

Una lista que puede estar vacía:


@forelse ($proyectos as $id => $proyecto)
    <li>{{ $proyecto['nombre'] }}</li>
@empty
    <li>Todavía no hay proyectos.</li>
@endforelse

Clases condicionales: @class


<p @class([
    'font-bold',
    'text-green-700' => $proyecto['metadatos']['calificacion'] >= 5,
    'text-red-700' => $proyecto['metadatos']['calificacion'] < 5,
])>
    {{ $proyecto['metadatos']['calificacion'] }}
</p>
  • Sin clave: siempre.
  • Con condición: solo si se cumple.

Estilos con Tailwind CSS

Sin componentes hechos: clases de utilidad, una propiedad cada una.

text-gray-500 · bg-whiteColor del texto y del fondo

<li class="rounded-lg bg-white p-4 shadow"> → una tarjeta

Compilar los estilos con Vite

  1. Vite lee resources/css/app.css, que importa Tailwind.
  2. Tailwind busca en las vistas las clases que usas y genera solo esas.
  3. El resultado va a public/build/.

npm install                  # como composer install, en node_modules/
npm run build                # compila a public/build/
npm run build -- --watch     # en un 2.º terminal: recompila solo

¿Una clase nueva? Hay que volver a compilar. node_modules/ y public/build/ no se suben.

@vite y asset()

Enlazar los ficheros compilados:


@vite(['resources/css/app.css', 'resources/js/app.js'])

Los ficheros que se sirven tal cual, en public/:


<img src="{{ asset('images/mp-logo.png') }}" alt="marcapersonalFP">

Layouts con componentes

components/layout.blade.php se usa como <x-layout>


@props(['titulo' => null])

<!DOCTYPE html>
<html lang="es">
<head>
    <title>{{ $titulo }} · {{ config('app.name') }}</title>
    @vite(['resources/css/app.css', 'resources/js/app.js'])
</head>
<body class="min-h-screen bg-gray-100 text-gray-800">
    <x-navbar />
    <main class="mx-auto max-w-5xl p-6">
        <h1 class="mb-6 text-3xl font-bold">{{ $titulo }}</h1>
        {{ $slot }}
    </main>
    <footer>{{ config('marcapersonalfp.centro') }}</footer>
</body>
</html>
Simplificado para que quepa: en el .md, el lang sale de app()->getLocale(), el título y el h1 dependen de que haya $titulo (@isset) y el pie lleva clases. Pulsaciones: @props declara los atributos; x-navbar es otro componente; el título; $slot es el hueco del contenido.

Una vista con el layout


<x-layout titulo="Pantalla principal">
    <p>Bienvenida a marcapersonalFP, la red de currículos del {{ $centro }}.</p>
</x-layout>

Lo de dentro va al {{ $slot }}; el atributo, a $titulo.

Si el valor es una expresión PHP, dos puntos delante:


<x-layout :titulo="'Vista detalle proyecto ' . $id">

Componer una página

  1. El layout pone el esqueleto: @vite, la barra, el título, el hueco {{ $slot }} y el pie
  2. <x-navbar /> se sustituye por el componente navbar
  3. La vista usa <x-layout titulo="…">: el atributo llega como $titulo
  4. Lo que va entre <x-layout> y </x-layout> ocupa el {{ $slot }}
  5. Cada <x-tarjeta-proyecto /> se sustituye por su componente
Paso 4: el bloque viaja de verdad desde la vista hasta el hueco $slot del layout. Es la idea clave: la vista solo escribe su contenido. Paso 5: el código del bloque se convierte en tres tarjetas, una por proyecto, cada una dibujada por el componente.

La barra de navegación


<nav class="bg-white shadow">
    <a href="{{ url('/') }}"><img src="{{ asset('images/mp-logo.png') }}" …></a>

    <a href="{{ route('proyectos.index') }}" @class([
        'text-blue-700' => request()->routeIs('proyectos.*'),
        'text-gray-600' => ! request()->routeIs('proyectos.*'),
    ])>Proyectos</a>
    …
</nav>

Enlaces con route() (5.3). routeIs('proyectos.*'): listado, detalle, alta y edición.

Componentes para piezas repetidas

components/tarjeta-proyecto.blade.php


@props(['proyecto', 'id'])

<li class="rounded-lg bg-white p-4 shadow">
    <h2 class="text-lg font-semibold">{{ $proyecto['nombre'] }}</h2>
    …
    <a href="{{ route('proyectos.show', $id) }}">Más información</a>
</li>

Se usa así; los dos puntos, porque los valores son variables:


<x-tarjeta-proyecto :proyecto="$proyecto" :id="$id" />

Puente

En v0

Cada página repetía su estructura y mezclaba el foreach con el HTML y el e() de cada dato.

En Laravel

Las vistas solo presentan; el layout se escribe una vez; {{ }} escapa sin acordarse.

Esto que hicimos a mano, el framework lo automatiza así.
