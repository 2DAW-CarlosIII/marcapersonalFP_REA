2.2. Sintaxis,
sentencias y salida

Las directivas echo y print

Seguimos con marcapersonalFP v0 en PHP plano

Seguimos sobre el proyecto vanilla_php de 2.1. Hoy: qué es una sentencia, dos reglas de sintaxis y las dos directivas de salida (echo y print). Tecla S: vista del ponente. Tecla O: vista general.

Sentencias

La unidad básica de un script PHP: instrucciones que el servidor ejecuta una tras otra, en orden. Cada una termina en punto y coma (;).


<?php
  $tituloCiclo = "Desarrollo de Aplicaciones Web";
  echo $tituloCiclo;
?>

Dos sentencias: una asignación y una de salida.

Primer clic: la línea 2 (asignación). Segundo clic: la línea 3 (salida). $tituloCiclo se usa de forma intuitiva, como "un nombre que guarda un valor": las variables, sus tipos y las constantes se ven en 2.3.

Espacios y saltos de línea

No importan para el intérprete. Lo que sí importa es el ; al final de cada sentencia.

Cómodo de leer


<?php
  $horas = 2000;
  echo $horas;
?>

Igual de válido


<?php $horas=2000;echo $horas; ?>

Los dos muestran 2000. Formatea como prefieras; por legibilidad, seguiremos una indentación consistente.

El ejemplo de la versión "apretada" es una ilustración añadida a la presentación (no está en el REA). Comprobado con PHP 8.3: las dos versiones imprimen 2000.

Mayúsculas y minúsculas

Variables

Sí distinguen: $tituloCiclo ≠ $TituloCiclo

Son dos variables distintas.

Palabras clave y funciones

No distinguen: echo = Echo = ECHO

Es la misma instrucción; por convención, siempre en minúscula.

Más adelante (Bloque 3), varias sentencias bajo una condición o un bucle se agrupan con llaves { }. De momento: secuencias simples.

Comprobado con PHP 8.3: usar $TituloCiclo teniendo definida $tituloCiclo da "Warning: Undefined variable $TituloCiclo", mientras que Echo y ECHO funcionan igual que echo.

Sentencias y efectos

Asignar

Guarda un valor en una variable: $horas = 2000;

No genera salida visible; solo cambia el estado interno del script.

Emitir salida

Envía texto a la respuesta HTTP: echo, print

Es la única forma de que algo calculado en el servidor llegue a verse en la página.

Los dos efectos con los que trabajaremos más a menudo en este bloque. Enlaza con 2.1: la salida es lo que viaja en la respuesta HTTP hacia el navegador.

Asignar no muestra nada


<?php
  $horas = 2000;      // asignación: sin efecto visible
  echo $horas;        // salida: esto sí llega al navegador
?>

Es fácil olvidarlo al empezar: para verlo en la página necesitas una sentencia de salida aparte.

Error típico de principiantes: escribir $horas = 2000; y esperar verlo en pantalla.

echo y print

No son funciones en sentido estricto:
son directivas del lenguaje (language constructs).

A efectos prácticos las usamos igual: para enviar texto a la salida. Existen ligeras diferencias entre ellas.

echo frente a print

echoprint
ArgumentosUno o varios, separados por comasSolo uno
Valor devueltoNinguno1 (por eso puede usarse dentro de una expresión)
ParéntesisOpcionalesOpcionales
Matiz sobre los paréntesis (según el manual de PHP): con un solo argumento no dan error, pero los paréntesis forman parte de la expresión, no de la sintaxis de echo. Con varios argumentos no se pueden envolver todos: echo("a", "b"); es un Parse Error.

echo con comas


<?php
  $nombreCiclo = "Desarrollo de Aplicaciones Web";
  $familia     = "Informática y Comunicaciones";
  $horas       = 2000;

  echo '<p>El ciclo <strong>',
       $nombreCiclo,
       '</strong> pertenece a la familia de ',
       $familia,
       ' y tiene ',
       $horas,
       ' horas.</p>';
?>

Varios argumentos separados por comas: PHP emite las piezas una tras otra, sin nada entre medias.

Repartido en líneas para leerlo mejor: los saltos de línea no importan.

En el REA la sentencia echo está en una sola línea; aquí se reparte en varias (mismo resultado, comprobado byte a byte) y se apoya en la regla de que los saltos de línea no importan. Como PHP no inserta nada entre las piezas, los espacios tienen que ir dentro de las cadenas.

print y el operador .

print acepta un único argumento: pegamos los trozos con el operador de concatenación (.).


<?php
  print '<p>El ciclo <strong>'
      . $nombreCiclo
      . '</strong> pertenece a la familia de '
      . $familia
      . ' y tiene '
      . $horas
      . ' horas.</p>';
?>

Con las mismas tres variables de antes.

El mismo HTML

El ciclo Desarrollo de Aplicaciones Web pertenece a la familia de Informática y Comunicaciones y tiene 2000 horas.

Con echo o con print, el navegador recibe lo mismo. La elección es, casi siempre, cuestión de estilo.

En este REA usaremos sobre todo echo: es la más habitual y admite varios argumentos sin concatenar.

Comprobado con PHP 8.3: las cuatro variantes (echo o print, en una línea o repartidas en varias) generan exactamente los mismos 139 bytes de HTML.

Curiosidad

print devuelve 1


<?php
  $resultado = print "Hola";
?>
  • Como print devuelve 1, es la única de las dos que puede aparecer dentro de otra expresión
  • No es un patrón que vayamos a usar: resulta confuso
  • Pero explica por qué el manual de PHP la describe como una expresión y echo no
Es el ejercicio 3. Al ejecutar $resultado = print "Hola"; echo $resultado; se ve "Hola1": print emite "Hola" y devuelve 1, que echo emite a continuación. El manual lo ilustra con el operador ternario: ($x) ? print 'a' : print 'b'; es válido, y ($x) ? echo 'a' : echo 'b'; no lo es.

Lo esencial

  • Un script es una secuencia de sentencias, cada una terminada en ;
  • Las variables distinguen mayúsculas; las palabras clave, no
  • Asignar no muestra nada: solo la salida llega al navegador
  • echo: varios argumentos con comas
    print: uno solo, con .

¿No ves el error?

Por defecto PHP no muestra los errores en el navegador (display_errors desactivado): verás una página en blanco, con un código 500.

En laradock/php-fpm/laravel.ini:


display_errors=On

Y, desde la carpeta laradock/:


docker compose up -d --build php-fpm

No sirve ini_set() dentro del script: un Parse error impide que se ejecute ninguna línea.

Relacionado con el ejercicio 3. Con display_errors desactivado, PHP responde con un 500 y el cuerpo vacío en lugar del mensaje del Parse error. Laradock incluye php-fpm/laravel.ini con display_errors=Off; se copia a conf.d, que PHP lee después del php.ini, así que gana aunque php8.4.ini tenga display_errors = On. Los .ini se copian a la imagen al construirla (igual que xdebug.ini): no basta con reiniciar, hay que reconstruir php-fpm. Conviene dejarlo activado durante el resto del curso. En producción se hace lo contrario: los errores se registran, no se muestran. El mismo ajuste se necesita en 2.4 (aviso "Undefined variable").
