5.2. Estructura de un proyecto

configuración y Artisan

Dónde va cada cosa, antes de escribir código

Laravel funciona por convenciones: si un fichero está en su sitio y se llama como debe, el framework lo encuentra solo. Tecla S: vista del ponente. Tecla O: vista general.

De vanilla_php a Laravel

Un script
por página		Un único public/index.php
src/Clases en app/, con espacio de nombres
HTML + PHPVistas en resources/views/
Constantes.env y config/
tests/tests/ y phpunit.xml, ya preparados

Las carpetas (1/2)

app/Controladores, modelos, clases propias
bootstrap/El arranque del framework
config/Un fichero por tema: app.php, session.php…
database/Migraciones, seeders, la base SQLite (Bloque 6)
public/index.php y los ficheros públicos

Las carpetas (2/2)

resources/Vistas, y fuentes de CSS y JavaScript
routes/web.php (páginas), console.php (comandos)
storage/Lo que genera el framework: registros, vistas compiladas
tests/Feature/ y Unit/
vendor/Las librerías de Composer. Nunca se toca

La raíz y app/

En la raíz

artisan, composer.json y .lock, .env y .env.example, package.json, vite.config.js, phpunit.xml

En app/, de serie

Http/Controllers/Controller.php (5.5) · Models/User.php (5.7) · Providers/AppServiceProvider.php (5.8)

Las demás subcarpetas aparecen al generar piezas con Artisan.

Una sola puerta: public/index.php


require __DIR__.'/../vendor/autoload.php';              // el autoload de Composer

$app = require_once __DIR__.'/../bootstrap/app.php';     // crea la aplicación

$app->handleRequest(Request::capture());                 // atiende la petición

Por eso el root del sitio de nginx apunta a public/ (5.1).

El viaje de una petición

  1. Request::capture(): todo entra por public/index.php
  2. Middleware (5.7): abre la sesión, comprueba el CSRF
  3. Router: busca la ruta en routes/web.php (5.3)
  4. Controlador (5.5): pide los datos al modelo
  5. Vista (5.4): genera el HTML con esos datos
  6. De vuelta por el middleware (guarda la sesión), al navegador
Un paso por pulsación; el punto recorre el tramo del paso actual. Insistir en el middleware: la petición lo cruza a la ida y la respuesta a la vuelta. En v0, cada script hacía todo esto él solo, empezando por session_start().

El patrón MVC

En v0, un mismo script mezcla datos, lógica y HTML.

Con MVC, cada pieza tiene una sola responsabilidad (5.8).

Una petición las recorre: controlador → modelo → controlador → vista.

Paso 1: cada línea del script de v0 viaja a la pieza que le corresponde; las dos de HTML acaban juntas en la vista. Paso 2: el punto recorre el ciclo completo de una petición. El foreach que genera el HTML es presentación: en Blade será @foreach (5.4).

Adiós a require_once

En v0, cada página cargaba lo que necesitaba:


require_once __DIR__ . '/../src/RA3_formularios.php';
require_once __DIR__ . '/../src/ValidadorCurriculo.php';   // que carga Curriculo.php

En Laravel, cada clase declara su espacio de nombres y las demás la importan con use:


namespace App\Http\Controllers;     // App\Http\Controllers\ProyectosController

use App\Models\User;                // "User" significa App\Models\User

El autoload de Composer (PSR-4)


"autoload": {
    "psr-4": {
        "App\\": "app/",
        "Database\\Factories\\": "database/factories/",
        "Database\\Seeders\\": "database/seeders/"
    }
}

App\Models\User → app/Models/User.php: la ruta del fichero coincide con el espacio de nombres.

La convención "una clase por fichero, con su nombre" de 3.5. Si cambias autoload: composer dump-autoload.

La configuración

  1. .env: los valores de esta instalación. Pueden ser secretos. No se sube.
  2. config/*.php: un array por tema; cada opción lee el .env con env() y tiene un valor por defecto. Sí se sube.
  3. config('fichero.clave'): así se lee desde el código.
En v0, NOMBRE_CENTRO o las opciones de session_start() estaban escritas en el código: para cambiarlas había que editar el programa.

Por ejemplo, config/app.php


'name' => env('APP_NAME', 'Laravel'),

'debug' => (bool) env('APP_DEBUG', false),

'locale' => env('APP_LOCALE', 'en'),

Y en cualquier parte de la aplicación:


config('app.name')      // 'marcapersonalFP', el APP_NAME de tu .env (5.1)

Tres reglas

  • env(), solo dentro de config/. Tras config:cache (producción), devuelve null fuera. En tu máquina, si lo ejecutas: config:clear.
  • APP_ENV: local, production o testing (lo fija phpunit.xml).
  • APP_DEBUG: con true, página de error detallada, como display_errors. Con false, "500 Server Error" y el detalle en storage/logs/laravel.log. En producción, siempre false.

Configuración propia

define('NOMBRE_CENTRO', …) de v0 pasa a config/marcapersonalfp.php:


<?php

return [

    // Nombre del centro que se muestra en la aplicación.
    'centro' => env('NOMBRE_CENTRO', 'CIFP Carlos III'),

];

config('marcapersonalfp.centro'). Variable nueva en .env → también en .env.example.

La sesión, ya configurada

Adiós a iniciarSesion() (4.2). En config/session.php:


'driver' => env('SESSION_DRIVER', 'database'),       // la tabla sessions (5.1)

'lifetime' => (int) env('SESSION_LIFETIME', 120),   // minutos de inactividad

'http_only' => env('SESSION_HTTP_ONLY', true),      // como en 4.1

'same_site' => env('SESSION_SAME_SITE', 'lax'),     // como en 4.1

Un middleware la abre en cada petición. La usaremos en 5.6 (flash) y 5.7 (login).

Para salir, exit.

Comandos propios: routes/console.php


Artisan::command('inspire', function () {
    $this->comment(Inspiring::quote());
})->purpose('Display an inspiring quote');
  • El nombre: php artisan inspire.
  • $this es el comando: info() (verde), comment() (amarillo), error() (rojo).
  • purpose(): la descripción de php artisan list.

Ejercicios (1/2)

  1. Recorre la estructura. ¿Dónde están la vista y la ruta de la bienvenida? ¿Por qué está vacía storage/framework/sessions/?
  2. Sigue una petición con Xdebug. pathMappings a /var/www/marcapersonalfp, punto de ruptura en public/index.php y F11 en handleRequest().
  3. Configuración regional. APP_LOCALE=es y APP_FAKER_LOCALE=es_ES.

Ejercicios (2/2)

  1. Un fichero de configuración propio. config/marcapersonalfp.php y NOMBRE_CENTRO en .env y .env.example.
  2. Un comando propio. marcapersonalfp:centro, en verde y con descripción.
  3. Investiga. vendor/composer/autoload_psr4.php. Y un error a propósito (SESSION_DRIVER=inexistente) con APP_DEBUG a true y a false.

Puente

En v0

NOMBRE_CENTRO, escrita en cada página; las opciones de la sesión, repetidas hasta iniciarSesion().

En Laravel

Lo que cambia por instalación, en .env; el resto, en config/, con un valor por defecto.

Esto que hicimos a mano, el framework lo automatiza así.

Comprueba tu solución (opcional)

  1. Copia RA5_2_EstructuraTest.php a tests/Feature/
  2. En el terminal de workspace, ejecuta ese test:

php artisan test --filter=RA5_2_EstructuraTest

Cubre los ejercicios 3 a 5.

Si todo está bien: Tests: 4 passed (10 assertions)
