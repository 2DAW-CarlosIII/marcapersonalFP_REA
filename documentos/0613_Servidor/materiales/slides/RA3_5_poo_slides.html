De los arrays a los objetos

Hemos representado un currículo con un array asociativo. Funciona, pero:

  • Nada garantiza su forma: $curriculo['alumo'] no da ningún error al crearlo
  • No se puede declarar su tipo con precisión: array $curriculos acepta cualquier array
  • Datos y operaciones van por separado: titulacion() no está unida al ciclo

Clase y objeto

Clase

El molde: qué datos tiene (propiedades) y qué sabe hacer (métodos).

Objeto

Una instancia concreta: el ciclo DAW y el ciclo DAM son dos objetos de la clase Ciclo.

El tipo compuesto object de 2.3 y 3.3. Base de todo Laravel: cada tabla de la BD, una clase.

Una primera clase


<?php
declare(strict_types=1);

class Ciclo
{
    public string $codCiclo;
    public string $nombre;
    public string $grado;

    public function __construct(string $codCiclo, string $nombre, string $grado)
    {
        $this->codCiclo = $codCiclo;
        $this->nombre   = $nombre;
        $this->grado    = $grado;
    }
}
Propiedad tipada: solo admite valores de ese tipo (las variables sueltas no lo permitían, 2.3). __construct: constructor, método especial que se ejecuta al crear el objeto. $this: el propio objeto; $this->codCiclo es "la propiedad codCiclo de este objeto".

new y ->


<?php
  $daw = new Ciclo('DAW', 'Desarrollo de Aplicaciones Web', 'Superior');
  $dam = new Ciclo('DAM', 'Desarrollo de Aplicaciones Multiplataforma', 'Superior');

  echo $daw->nombre;   // Desarrollo de Aplicaciones Web
  echo $dam->codCiclo; // DAM
?>

Convención: clases en PascalCase (Ciclo); propiedades y métodos en camelCase.

Promoción de propiedades

Declarar, repetir como parámetro y asignar es repetitivo. Desde PHP 8, un parámetro con visibilidad se convierte a la vez en propiedad.


<?php
class Ciclo
{
    public function __construct(
        public string $codCiclo,
        public string $nombre,
        public string $grado,
    ) {
    }
}

Exactamente equivalente a la diapositiva anterior. Lo usaremos siempre que podamos.

Métodos

Una función dentro de una clase, que trabaja con los datos de su objeto, a través de $this.


<?php
class Ciclo
{
    // ... constructor ...

    public function titulacion(): string
    {
        return $this->grado === 'Superior' ? 'Técnico Superior' : 'Técnico';
    }
}

$daw = new Ciclo('DAW', 'Desarrollo de Aplicaciones Web', 'Superior');
echo $daw->titulacion();   // Técnico Superior
?>

Compara con titulacion($grado) de 3.4: ahora el ciclo ya lo conoce.

Visibilidad

Encapsulación: ocultar los datos internos (private) y ofrecer solo los métodos necesarios.

Controlar cómo cambia el estado


<?php
class Curriculo
{
    private bool $publicado = false;

    public function __construct(public string $alumno) {
    }

    public function publicar(): void
    {
        $this->publicado = true;
    }

    public function estaPublicado(): bool
    {
        return $this->publicado;
    }
}
// $curriculo->publicado = false;  // Error: Cannot access private property
?>

No queremos que nadie "despublique" asignando false a mano.

Propiedades de solo lectura: readonly

Se puede leer, pero asignar solo una vez, dentro de la clase.


<?php
class Ciclo
{
    public function __construct(
        public readonly string $codCiclo,
        public readonly string $nombre,
    ) {
    }
}
$daw = new Ciclo('DAW', 'Desarrollo de Aplicaciones Web');
// $daw->codCiclo = 'DAM';  // Error: Cannot modify readonly property
?>

Con private + métodos controlamos cómo cambia; con readonly, que no cambia.

Constantes de clase

En 2.3: const —a diferencia de define()— puede usarse dentro de una clase. Pertenece a la clase, no a cada objeto.


<?php
class Ciclo
{
    public const GRADO_MEDIO    = 'Medio';
    public const GRADO_SUPERIOR = 'Superior';

    public function titulacion(): string
    {
        return $this->grado === self::GRADO_SUPERIOR ? 'Técnico Superior' : 'Técnico';
    }
}
?>

Se accede con ::: fuera, Ciclo::GRADO_SUPERIOR; dentro, self::…. Un error tipográfico da un error inmediato, a diferencia de un string mal escrito.

Métodos estáticos: fábrica

Pertenecen a la clase, sin crear ningún objeto. Un método de fábrica construye un objeto a partir de otros datos.


<?php
class Ciclo
{
    // ...

    public static function desdeArray(array $datos): self
    {
        return new self($datos['codCiclo'], $datos['nombre'], $datos['grado']);
    }
}

$dam = Ciclo::desdeArray(['codCiclo' => 'DAM', 'nombre' => '…', 'grado' => 'Superior']);
?>

Dentro no existe $this. En el Bloque 4: Ciclo::find(1), Ciclo::create([...]).

Una propiedad static es compartida por todos los objetos de la clase. Igual que la variable static de una función (2.4), no sobrevive entre peticiones: cada petición ejecuta el script desde cero.

Los objetos no se copian

En 3.3, asignar un array copiaba. Con objetos no: la variable guarda un identificador.


<?php
  $curriculo = new Curriculo('Ana López');
  $otro = $curriculo;

  $otro->publicar();
  echo $curriculo->estaPublicado() ? 'publicado' : 'en borrador';   // publicado
?>

Las dos variables apuntan al mismo objeto. Para una copia independiente: clone $curriculo.

Objetos dentro de objetos

Un currículo tiene un ciclo (composición).


<?php
class Curriculo
{
    public function __construct(
        public readonly Ciclo $ciclo,
        public readonly ?string $videoCurriculum = null,
    ) {
    }
}
// $curriculo->ciclo->nombre
?>

Una clase como tipo declarado, igual que int o string: si le pasas otra cosa, TypeError.

Herencia: extends

Todas las entidades del proyecto comparten cosas (un id). Una clase padre, y las demás heredan.


<?php
abstract class Modelo
{
    public function __construct(public readonly int $id) {
    }

    abstract public function descripcion(): string;
}

class Ciclo extends Modelo
{
    public function __construct(
        int $id,
        public readonly string $codCiclo,
        public readonly string $nombre,
    ) {
        parent::__construct($id);
    }

    public function descripcion(): string
    {
        return $this->codCiclo . ' — ' . $this->nombre;
    }
}
?>
$daw->id funciona aunque Ciclo no declare id. Si la hija define constructor propio, debe llamar a parent::__construct(...). $id en el constructor de Ciclo no lleva visibilidad: no es propiedad nueva, solo un parámetro que se pasa al padre.

abstract

Clase abstracta

No se puede instanciar (new Modelo(1) da error): solo sirve de base.

Método abstracto

Declara su firma sin cuerpo y obliga a cada hija a implementarlo.

Un objeto de una clase hija es también del tipo de la padre: un parámetro Modelo acepta un Ciclo o un Curriculo.

Puente al Bloque 4. class Ciclo extends Model: la clase padre la escribe Laravel.

Interfaces: "sabe hacer"

La herencia expresa "es un". Una interfaz expresa "sabe hacer", sin implementar.


<?php
interface Publicable
{
    public function publicar(): void;
    public function estaPublicado(): bool;
}

class Curriculo extends Modelo implements Publicable
{
    // publicar() y estaPublicado(), como antes
}
?>

Una clase hereda de una padre, pero implementa varias interfaces. $curriculo instanceof Publicable comprueba en tiempo de ejecución.

Organizar las clases en ficheros

Como en 3.4, en src/, que solo define. Convención: una clase por fichero, con su mismo nombre: src/Ciclo.php, src/Curriculo.php…

Cada fichero carga con require_once lo que necesita: Ciclo.php necesita Modelo.php, porque hereda de ella.

Puente al Bloque 4. En Laravel, App\Models\Ciclo vive en app/Models/Ciclo.php: esa correspondencia nombre-ruta es la que permite al autoload de Composer cargar sin require_once.
