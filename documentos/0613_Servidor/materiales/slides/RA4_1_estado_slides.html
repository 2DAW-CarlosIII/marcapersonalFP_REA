¿Por qué lo olvida todo?

Cada petición ejecuta el script desde cero (2.4): variables, arrays y objetos desaparecen al enviar la respuesta.

HTTP no tiene estado

Cada petición llega sin relación con las anteriores: nada indica qué peticiones vienen del mismo navegador.

Por eso el alta de 3.8 no podía guardar nada. Con dos alumnos usando la aplicación a la vez, sus peticiones se mezclan en el servidor.

Dos mecanismos para recordar

Cookies

La información se guarda en el navegador, que la devuelve en cada petición.

Sesiones

La información se guarda en el servidor; el navegador solo guarda un identificador.

En la práctica se usan juntos: la sesión se apoya en una cookie.

Una cookie, en las cabeceras

  1. En una respuesta, el servidor envía Set-Cookie: ultimo_ciclo=DAW
  2. En cada petición siguiente a ese sitio, el navegador envía Cookie: ultimo_ciclo=DAW

Un par nombre-valor que el servidor pide al navegador que guarde.

setcookie() y $_COOKIE


<?php
// Guardar: el navegador la conservará 30 días.
setcookie('ultimo_ciclo', 'DAW', [
    'expires'  => time() + 60 * 60 * 24 * 30,
    'httponly' => true,
    'samesite' => 'Lax',
]);

// Leer: llega en las peticiones SIGUIENTES.
$ciclo = $_COOKIE['ultimo_ciclo'] ?? '';
?>

Tres detalles

  • $_COOKIE refleja la petición: lo que acabas de crear con setcookie() no está ahí hasta la siguiente.
  • Con expires, cookie persistente; sin él, de sesión: se borra al cerrar el navegador.
  • El valor viene del cliente: se ve y se cambia con F12. Es un dato de entrada más, como $_POST.

Las cabeceras, antes que el cuerpo

setcookie(), header() y session_start() añaden cabeceras, que viajan antes que el HTML.

Con la primera salida (un echo, HTML, una línea en blanco antes de <?php) se envían las cabeceras, y ya no se pueden añadir más:


Cannot modify header information - headers already sent

Por eso: primero la lógica en PHP, después la página (como en 3.6 y 3.8).

Sesiones: el servidor recuerda


<?php
session_start();

$_SESSION['visitas'] = ($_SESSION['visitas'] ?? 0) + 1;
?>
<p>Has visitado esta página <?= $_SESSION['visitas'] ?> veces.</p>

Para lo que no debe ver ni cambiar el usuario, o no cabe en una cookie.

¿Qué hace session_start()?

  1. Busca la cookie PHPSESSID. Si no llega, sesión nueva: identificador aleatorio y Set-Cookie: PHPSESSID=…. Si llega, carga sus datos.
  2. Durante el script, $_SESSION es un array normal.
  3. Al terminar, PHP guarda $_SESSION en el servidor hasta la siguiente petición con ese identificador.

Cada navegador, su sesión: una ventana privada empieza vacía.

En la sesión: datos, no objetos

Para guardar $_SESSION, PHP la serializa (la convierte en texto).

Un objeto también se puede guardar, pero su clase tiene que estar cargada antes de session_start() para reconstruirlo.

Guardaremos los datos de cada currículo; el listado volverá a construir los objetos.

La misma idea que con la base de datos: se guardan filas, la aplicación las convierte en objetos.

Además, las cookies viajan en cada petición, también en la de cada imagen y hoja de estilos: cuantas más y más grandes, más tráfico.

Proteger la cookie de sesión

Quien conozca tu PHPSESSID puede suplantar tu sesión.

  • HttpOnly: el JavaScript no la lee; un XSS (3.6) no podría robarla.
  • SameSite=Lax: no viaja en POST desde otro sitio; dificulta el CSRF.

session_start([
    'cookie_httponly' => true,
    'cookie_samesite' => 'Lax',
]);

Secure (solo HTTPS): siempre en producción; aquí trabajamos con HTTP.

Por fin: POST/Redirect/GET

En 3.6 nos faltaba recordar un mensaje entre dos peticiones. Con la sesión:


$_SESSION['mensaje'] = 'Currículo dado de alta: Ana López (DAW)';
header('Location: RA4_curriculos.php', true, 303);
exit;
  • 303 See Other: el navegador pide la otra página con GET.
  • exit: tras redirigir, no tiene sentido generar HTML.

Mensaje flash

En la página de destino, el mensaje se lee y se borra:


$mensaje = $_SESSION['mensaje'] ?? null;
unset($_SESSION['mensaje']);

Se muestra una sola vez: al pulsar F5 en el listado, ni reaparece el mensaje ni se reenvía el formulario.
