2.4. Ámbitos
de las variables

Dónde existe cada variable

Seguimos con marcapersonalFP v0 en PHP plano

Último contenido teórico del bloque (CE h). Para explicar el ámbito hace falta la sintaxis mínima de una función, que se formaliza en el Bloque 3. Tecla S: vista del ponente. Tecla O: vista general.

Ámbito

La parte del script donde una variable existe
y puede usarse.

Hasta ahora, cada script era una única secuencia de sentencias: todo vivía en el ámbito global del fichero.

Funciones, en avance

Bloques de código con nombre que solo se ejecutan cuando se llaman.


<?php
  function saludo() {
    echo "Hola";
  }

  saludo();   // así se llama: por su nombre, seguido de ()
?>

Solo la sintaxis mínima para entender el ámbito. Las formalizamos (parámetros, valores de retorno…) en el Bloque 3.

Ámbito local

Una variable creada dentro de una función es local: solo existe mientras la función se ejecuta.


<?php
  function mostrarCiclo() {
    $nombreCiclo = "Desarrollo de Aplicaciones Web";
    echo '<p>', $nombreCiclo, '</p>';
  }

  mostrarCiclo();

  // echo $nombreCiclo;   // Warning: Undefined variable $nombreCiclo
?>

Desde fuera, nada puede verla.

Primer clic: la variable local. Segundo: la llamada. Tercero: el intento de usarla fuera (comentado; en el ejercicio 1 se descomenta). En PHP 8 el aviso es un Warning; el script sigue ejecutándose.

La función no ve lo de fuera

Distinto de otros lenguajes (JavaScript): en PHP una función no ve automáticamente las variables globales, aunque estén definidas antes de llamarla.


<?php
  $nombreCiclo = "Desarrollo de Aplicaciones Web";

  function mostrarCiclo() {
    // Warning: Undefined variable $nombreCiclo
    echo '<p>', $nombreCiclo, '</p>';
  }

  mostrarCiclo();
?>

Para PHP son dos ámbitos distintos y separados.

En el REA el comentario del aviso va al final de la línea del echo; aquí se coloca encima para que quepa en la diapositiva.

global

Si una función necesita leer o modificar una variable global, hay que decírselo explícitamente.


<?php
  $totalCiclosMostrados = 0;

  function registrarVisita() {
    global $totalCiclosMostrados;
    $totalCiclosMostrados++;
  }

  registrarVisita();
  registrarVisita();
  registrarVisita();

  echo '<p>Ciclos mostrados: ', $totalCiclosMostrados, '</p>';
?>

Se muestra 3. global no crea una variable nueva: enlaza el nombre local con la global del mismo nombre.

En el REA el último echo lleva al final un comentario con el resultado (// 3); aquí se comenta en la frase de debajo.

Constantes: la excepción

Las constantes de 2.3 no siguen estas reglas: son accesibles en cualquier función, sin global.


<?php
  define('NOMBRE_CENTRO', 'CIFP Carlos III');

  function pie() {
    // Sin "global": las constantes son accesibles en cualquier ámbito
    echo '<footer>', NOMBRE_CENTRO, '</footer>';
  }

  pie();
?>

Por eso son útiles para valores fijos de configuración: el nombre del centro, una clave de API…

Variables superglobales

PHP trae variables propias que comparten la propiedad de las constantes: disponibles en cualquier ámbito, sin global.

$_GET · $_POST

$_SERVER · $_SESSION

Las usaremos con detalle en formularios (Bloque 3) y sesiones (Bloque 4).

Variables estáticas

Las locales se destruyen al terminar la función y se recrean —vacías— en la siguiente llamada. static hace que una variable conserve su valor entre llamadas.


<?php
  function contadorVisitas() {
    static $visitas = 0;
    $visitas++;
    echo '<p>Visita número ', $visitas, '</p>';
  }

  contadorVisitas();   // Visita número 1
  contadorVisitas();   // Visita número 2
  contadorVisitas();   // Visita número 3
?>

Sin static, $visitas valdría 0 al inicio de cada llamada y nunca pasaría de «Visita número 1».

Los clics recorren: la función, la primera llamada, la segunda y la tercera.

Ojo con «entre llamadas»

Una misma ejecución

Las tres llamadas a contadorVisitas() muestran 1, 2 y 3.

Recargas la página

Petición HTTP nueva: el contador vuelve a empezar por 1.

Cada petición ejecuta el script desde cero. Al terminar la respuesta no queda memoria de nada, tampoco de las variables static.

Para conservar datos entre peticiones hacen falta mecanismos de estado explícitos: sesiones, cookies o una base de datos (bloques posteriores).

Enlaza con el flujo petición-respuesta de 2.1: el servidor ejecuta el script para cada petición. Es el motivo del ejercicio 4: recargar varias veces y explicar por qué el contador no sigue por el 4, el 5…

Lo esencial

  • Una variable local solo existe dentro de su función
  • Una función no ve las variables globales, salvo que uses global
  • Las constantes y las superglobales se ven en cualquier ámbito
  • static conserva el valor entre llamadas… solo dentro de una misma petición

Las superglobales son variables predefinidas disponibles en todos los ámbitos sin usar global: $GLOBALS, $_SERVER, $_GET, $_POST, $_FILES, $_COOKIE, $_SESSION, $_REQUEST y $_ENV.
