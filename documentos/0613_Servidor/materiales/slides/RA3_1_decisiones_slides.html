Decidir qué se ejecuta

Un grupo de sentencias que se ejecuta
solo si se cumple una condición.

Recuerda 2.1: el navegador solo recibe el HTML resultante. El código de la rama que no se ejecuta ni siquiera llega al cliente.

if

Si la condición vale true, se ejecuta el bloque entre llaves { } (anunciadas en 2.2).


<?php
  $grado = 'Superior';

  if ($grado === 'Superior') {
    echo '<p>Ciclo de Grado Superior: da acceso a la universidad.</p>';
  }
?>

elseif y else


<?php
  if ($grado === 'Superior') {
    echo '<p>Ciclo de Grado Superior: da acceso a la universidad.</p>';
  } elseif ($grado === 'Medio') {
    echo '<p>Ciclo de Grado Medio: da acceso a un Grado Superior.</p>';
  } else {
    echo '<p>Grado desconocido.</p>';
  }
?>

Las condiciones se comprueban en orden; en cuanto una se cumple, las siguientes ya no se evalúan.

Dos costumbres del REA

  • Comparamos con === (2.3): sin conversiones de tipo inesperadas
  • Escribimos siempre las llaves, aunque el bloque tenga una sola sentencia

Sin llaves, al añadir después una segunda sentencia es fácil creer que está dentro del if… y no lo está.

Condiciones compuestas

Los operadores lógicos de 2.3 cobran aquí todo su sentido:

OperadorLa condición vale true si…
$a && $b…ambas son true
$a || $b…al menos una es true
!$a…$a es false

¿Está completo el currículo?


<?php
  $videoCurriculum = 'https://youtu.be/curriculo1';
  $textoCurriculum = '';

  if ($videoCurriculum !== '' && $textoCurriculum !== '') {
    echo '<p>Currículo completo</p>';
  } elseif ($videoCurriculum !== '' || $textoCurriculum !== '') {
    echo '<p>Currículo incompleto</p>';
  } else {
    echo '<p>Currículo vacío</p>';
  }
?>

El orden importa: primero la condición más exigente.

video_curriculum y texto_curriculum son campos reales del Curriculo en el Swagger del proyecto. Con estos valores sale "Currículo incompleto".

¿Y si la condición no es un bool?

PHP la convierte a bool: if ($textoCurriculum) es válido.

Cómodo…

'' se convierte en false; un texto, en true.

…pero con sorpresas

Preferimos la comparación explícita: $textoCurriculum !== ''

Las sorpresas, en el ejercicio de investigación.

switch

Una misma expresión comparada con muchos valores:


<?php
  switch ($codFamilia) {
    case 'INF':
      $familia = 'Informática y Comunicaciones';
      break;
    case 'ADG':
      $familia = 'Administración y Gestión';
      break;
    default:
      $familia = 'Familia desconocida';
  }
?>

Sin break, la ejecución continúa en el case siguiente. Y compara con ==.

Ejemplo de la comparación débil: con $codFamilia = '1', un case 1: se cumpliría aunque uno sea string y el otro int.

match (PHP 8)


<?php
  $codFamilia = 'INF';

  $familia = match ($codFamilia) {
    'INF'   => 'Informática y Comunicaciones',
    'ADG'   => 'Administración y Gestión',
    'COM'   => 'Comercio y Marketing',
    default => 'Familia desconocida',
  };

  echo '<p>Familia profesional: ', $familia, '</p>';
?>

Varios valores pueden compartir resultado: 'DAW', 'DAM', 'ASIR' => …

switch frente a match

switchmatch
Compara con== (convierte tipos)=== (estricta)
breakEn cada caseNo existe
¿Devuelve valor?No: es una sentenciaSí: es una expresión
Sin coincidenciaNo hace nadaUnhandledMatchError

Coherentes con ===: para elegir un valor entre varios, match.

"Sin coincidencia" significa: ningún caso coincide y no hay default. switch no hace nada; match lanza un UnhandledMatchError.

El operador ternario

Elegir entre dos valores en una sola expresión:


condición ? valorSiTrue : valorSiFalse
        

<?php
  $grado = 'Superior';
  $titulo = $grado === 'Superior' ? 'Técnico Superior' : 'Técnico';
  echo '<p>Titulación: ', $titulo, '</p>';
?>

Para casos cortos. ¿Ternarios anidados? Mejor un if o un match.

El operador ??

El valor de la izquierda si existe y no es null; si no, el de la derecha.


<?php
  $curriculo = ['alumno' => 'Ana López', 'ciclo' => 'DAW'];

  echo '<p>Vídeo: ', $curriculo['video'] ?? 'Sin vídeo de presentación', '</p>';
?>
  • Sin ??: warning Undefined array key "video"
  • Imprescindible en 3.6, con los formularios: nunca damos por hecho que llega un campo

Decisiones en el HTML

Sintaxis alternativa: { se cambia por : y } por endif;


<?php $publicado = true; ?>

<?php if ($publicado): ?>
  <p class="estado">Currículo publicado</p>
<?php else: ?>
  <p class="estado">Currículo en borrador</p>
<?php endif; ?>

El HTML queda fuera de echo. El servidor envía uno u otro párrafo, nunca los dos.

En el Bloque 4, Blade: @if … @else … @endif

Lo esencial

  • if / elseif / else, siempre con llaves y con ===
  • &&, || y ! combinan condiciones
  • match elige un valor entre varios, con comparación estricta
  • Ternario para dos valores; ?? para un valor que puede no existir
  • Sintaxis alternativa para decidir qué HTML se envía

Ejercicios (2/2)

  1. Ternario y ??. La titulación y el currículo sin clave 'video'.
  2. Sintaxis alternativa. El ejemplo de $publicado. Mira el código fuente (Ctrl+U): ¿aparece "Currículo en borrador"?
  3. Investiga. ¿Qué valores se convierten en false? ¿Qué muestra if ('0')? ¿Y if ('0.0')? ¿Por qué preferimos comparar explícitamente?
Respuestas del ejercicio 6 (documentación: "Converting to boolean"). Se convierten en false: false, 0, 0.0 (y -0.0), el string vacío '', el string '0', el array vacío [] y null. Todo lo demás es true. if ('0') muestra "no": el string '0' es falso. if ('0.0') muestra "sí": solo el string '0' exacto es falso, '0.0' es un string no vacío y distinto de '0'. Por eso comparamos explícitamente: un campo de formulario con el valor '0' sería "falso" aunque el usuario haya escrito algo.
