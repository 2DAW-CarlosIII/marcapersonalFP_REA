5.3. Rutas

Qué código atiende cada petición

Adiós a "un script por página"

Primera fila del plan del bloque: "un script en public/ por página → rutas y controladores". Aquí, las rutas; los controladores, en 5.5. Tecla S: vista del ponente. Tecla O: vista general.

De un script a una ruta

En v0

La dirección es el fichero: /RA2_proyectoListado.php

Los datos, en $_GET, sin comprobar.

En Laravel

routes/web.php asocia método + dirección → acción


Route::get('/', function () {
    return view('welcome');
});

¿Qué ganamos?

  • Direcciones limpias: /proyectos/show/7, no /RA3_detalle.php?id=7
  • Un solo lugar con todas las páginas de la aplicación
  • Los datos, dentro de la dirección, y comprobados por el framework
  • Reorganizar el código sin cambiar las direcciones

Métodos HTTP

GETConsultar, sin cambiar nadaRoute::get()
POSTCrear algo nuevoRoute::post()
PUT / PATCHModificarRoute::put()
DELETEBorrarRoute::delete()

Dirección que existe, pero otro método: 405. Formularios: solo GET y POST (5.6).

¿Qué devuelve una acción?

  • Un texto → HTML. En este apartado.
  • Un array → JSON. Así responderá la API (Bloque 7).
  • Una vista (5.4) o una redirección (5.6).

Parámetros


Route::get('proyectos/show/{id}', function ($id) {
    return 'Vista detalle proyecto ' . $id;
});

/proyectos/show/7 → "Vista detalle proyecto 7". /proyectos/show → 404.

Opcional: ? y un valor por defecto


Route::get('perfil/{id?}', function ($id = null) {
    // ...
});

Restricciones


Route::get('proyectos/show/{id}', function ($id) {
    return 'Vista detalle proyecto ' . $id;
})->whereNumber('id');
whereNumber('id')Solo dígitos
whereAlpha('nombre')Solo letras
where('ciclo', 'DAW|DAM|ASIR')Una expresión regular

/proyectos/show/abc → 404, sin ejecutar nuestro código.

Lo que devuelves, escápalo

El parámetro lo escribe el usuario en la dirección. Como en 3.6:


Route::get('hola/{nombre?}', function ($nombre = 'mundo') {
    return '¡Hola, ' . e($nombre) . '!';
});

e() también existe en Laravel. En 5.4, Blade escapará solo.

Rutas con nombre


Route::get('proyectos/show/{id}', function ($id) {
    return 'Vista detalle proyecto ' . $id;
})->whereNumber('id')->name('proyectos.show');

route('proyectos.show', 7);    // http://marcapersonalfp.test/proyectos/show/7

Si cambia la dirección, los enlaces hechos con route() se actualizan solos.

Convenio: recurso.acción → proyectos.index, proyectos.show…

Grupos de rutas


Route::prefix('proyectos')->name('proyectos.')->group(function () {
    Route::get('/', function () { /* ... */ })->name('index');
    Route::get('create', function () { /* ... */ })->name('create');
});
  • prefix('proyectos'): antepone proyectos/ a cada dirección.
  • name('proyectos.'): antepone proyectos. a cada nombre.
  • Un grupo también puede compartir middleware (5.7).

Cómo decide el router

  1. Llega GET /proyectos/show/7
  2. El router compara las rutas en orden
  3. Gana la primera que coincide: el 7 pasa a $id
  4. Con abc, ninguna coincide: 404, sin ejecutar nuestro código
Paso 2: la barra amarilla recorre las rutas en orden. Paso 4: ahora con abc; la restricción descarta la tercera y ninguna otra encaja. En v0, esta comprobación del id la teníamos que hacer nosotros con $_GET.

El orden importa


Route::get('proyectos/{id}', fn ($id) => "Proyecto $id");     // antes...
Route::get('proyectos/create', fn () => 'Añadir proyecto');   // ...nunca se alcanza

/proyectos/create coincide con la primera, con $id = 'create'.

  • Rutas fijas antes que las que llevan parámetros…
  • …y el parámetro, restringido: whereNumber('id').

Artisan: route:list


php artisan route:list
php artisan route:list --path=proyectos

Método, dirección, nombre y acción de cada ruta.

También salen las del framework, como /up: ¿está viva la aplicación?

Puente

En v0

Cada dirección, un fichero de public/; los datos, en $_GET, sin comprobar.

En Laravel

Todas las direcciones en routes/web.php; los parámetros, en la dirección y con restricciones.

Esto que hicimos a mano, el framework lo automatiza así.
