5.5. Controladores

La C de MVC

Las rutas, solo un índice de direcciones

Al terminar 5.4, routes/web.php tenía datos y preparaba las vistas. Aquí lo ordenamos con controladores. Tecla S: vista del ponente. Tecla O: vista general.

Demasiado código en las rutas

routes/web.php ya tiene datos y prepara las vistas. Con cuatro rutas se lee; con cuarenta, no.

Un controlador agrupa las acciones de un recurso. Para cada petición:

  1. recibe los datos de la petición, como el {id};
  2. pide al modelo los datos que necesita;
  3. elige la vista y se los pasa.

De la ruta al controlador

  1. Antes: la función de la ruta lo hace todo: tiene los datos y elige la vista
  2. Se mudan a ProyectosController: los datos, a una propiedad; la vista, a show()
  3. La ruta solo apunta: [ProyectosController::class, 'show']
  4. Después: ruta → show(7) → $arrayProyectos[7] → view('proyectos.show')
Paso 2: las dos piezas viajan de verdad desde la función de la ruta al controlador. Paso 3: lo que queda en routes/web.php es un índice de direcciones. Los datos tampoco se quedarán en el controlador: en 5.8 irán a una clase propia y en el Bloque 6, a la base de datos.

Un controlador básico


php artisan make:controller ProyectosController

En app/Http/Controllers/, espacio de nombres App\Http\Controllers (5.2):


<?php

namespace App\Http\Controllers;

use Illuminate\Http\Request;

class ProyectosController extends Controller
{
    //
}

Sufijo Controller; todos heredan de Controller.

Cada método público, una acción


use Illuminate\View\View;

class ProyectosController extends Controller
{
    public function index(): View
    {
        return view('proyectos.index', ['proyectos' => $this->arrayProyectos]);
    }
}
  • Devuelve lo mismo que las funciones de las rutas: una vista, un texto, un array…
  • View: el tipo de lo que devuelve view(). Como en 3.4, documenta y PHP lo comprueba.

Rutas que apuntan a controladores

En lugar de una función, la clase y el método:


use App\Http\Controllers\ProyectosController;

Route::get('proyectos', [ProyectosController::class, 'index'])->name('proyectos.index');

ProyectosController::class → 'App\Http\Controllers\ProyectosController'

El use permite escribirlo abreviado.

Un grupo, un controlador


Route::controller(ProyectosController::class)->prefix('proyectos')->name('proyectos.')
    ->group(function () {
        Route::get('/', 'index')->name('index');
        Route::get('show/{id}', 'show')->whereNumber('id')->name('show');
        Route::get('create', 'create')->name('create');
        Route::get('edit/{id}', 'edit')->whereNumber('id')->name('edit');
    });

Route::controller() se combina con el prefijo y el nombre de 5.3: cada ruta solo dice su método.

Los parámetros llegan al método


public function show(int $id): View
{
    abort_unless(isset($this->arrayProyectos[$id]), 404);

    return view('proyectos.show', [
        'proyecto' => $this->arrayProyectos[$id],
        'id' => $id,
    ]);
}
  • Por su nombre: {id} → $id. Llega '7'; int lo convierte (whereNumber lo garantiza).
  • Sin abort_unless(), /proyectos/show/99 daría un 500.

Cortar la petición: abort()

abort(404)Siempre
abort_if($condicion, 404)Si se cumple
abort_unless($condicion, 404)Si no se cumple

En v0: http_response_code(404) y exit, o el 403 de exigirRol() (4.4).

Una propiedad, como en 3.5. No es su sitio: guardar datos es cosa del modelo.

En 5.8, a una clase propia; en el Bloque 6, a la base de datos. El controlador apenas cambiará: solo coordina.

Controladores invocables


php artisan make:controller HomeController --invokable
        

class HomeController extends Controller
{
    public function __invoke(): View
    {
        return view('home', ['centro' => config('marcapersonalfp.centro')]);
    }
}

En la ruta, solo la clase:


Route::get('/', HomeController::class);

Puente

En v0

Cada script leía la petición, preparaba los datos, decidía qué responder y escribía el HTML.

En Laravel

El controlador coordina: recibe la petición, pide los datos y elige la vista. abort() sustituye a http_response_code() y exit.

Esto que hicimos a mano, el framework lo automatiza así.
